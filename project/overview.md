# LightHeadless CMS — Project Overview

## Что это

Легковесная Headless CMS на Go. Единый бинарный файл без внешних зависимостей.
Целевая аудитория — владельцы лендингов и небольших сайтов, которым нужен простой инструмент
для сбора заявок и публикации новостей. Установка — скопировать файл и запустить.

## Ключевые характеристики

- **Single binary** — один файл, `./cms`, всё внутри (шаблоны, статика — embed)
- **SQLite** — база данных в одном файле рядом с бинарником, без сервера
- **Zero config** — при первом запуске создаёт БД, таблицы, выводит случайный пароль в консоль
- **HTMX + Go templates** — фронтенд без SPA, без Node.js, без сборки
- **Solo + AI разработка** — код должен быть простым, читаемым, хорошо покрытым тестами

## Что умеет

### Публичные API (для лендингов)
- `POST /api/leads` — принять заявку из HTML формы
- `GET /api/news` — список новостей (JSON, с пагинацией)
- `GET /api/news/{id}` — конкретная новость (JSON)
- `GET /uploads/{filename}` — статические файлы (изображения)

### Административная панель (`/admin`)
- **Заявки:** список, фильтр по статусу, поиск, детали, ручная смена статуса, экспорт CSV, повторная отправка в Битрикс24
- **Новости:** список, создание/редактирование/удаление, загрузка изображений, Markdown
- **Настройки:** email/пароль администратора, URL вебхука Битрикс24, включение интеграции

## Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Язык | Go 1.21+ | Single binary, производительность, stdlib достаточно |
| БД | SQLite (modernc/sqlite — pure Go) | Нет CGO, нет внешних зависимостей |
| HTTP | net/http (stdlib) | Достаточно для проекта, без фреймворков |
| Фронтенд | HTML5 + HTMX + Alpine.js | Нет сборки, нет Node.js |
| Шаблоны | html/template (embed) | Встроено в Go, XSS-safe по умолчанию |
| Markdown | goldmark | Популярная, CommonMark-совместимая |
| Пароли | bcrypt | Стандарт |
| Сессии | SQLite таблица `sessions` | Persistence после рестарта |
| Rate limit | In-memory sync.Map (IP-based) | Без Redis, для MVP достаточно |

## Ключевые архитектурные решения (зафиксированы)

1. **SQLite WAL mode** включён при инициализации — решает проблему конкурентных записей
2. **Sessions в SQLite** — сессии не теряются при рестарте сервера
3. **Random password** при первом запуске — выводится в stdout, не хардкодится
4. **Bitrix24 worker pool** — 10 воркеров, buffered channel 100, drain при graceful shutdown
5. **IP rate limit** на `/api/leads` — in-memory, без внешних зависимостей
6. **HMAC на сессионных cookies** — подпись чтобы нельзя было подделать session ID
7. **CSV streaming** через `sql.Rows` — без загрузки всех записей в память
8. **Indeksy** на `leads(status, created_at)` и `news(date)` — при создании таблиц
9. **modernc/sqlite** (pure Go) вместо mattn/go-sqlite3 — нет CGO, проще cross-compilation

## Ограничения (осознанные трейдоффы)

- Один администратор (не multi-user)
- Только SQLite (нет PostgreSQL/MySQL)
- Rate limit сбрасывается при рестарте (in-memory)
- Без встроенного HTTPS — запускать за nginx/caddy (задокументировано)
- Нет встроенного backup — SQLite файл копируется вручную

## Критерии готовности MVP

- [ ] `./cms` запускается без аргументов, выводит пароль, поднимает сервер на :8080
- [ ] Форма на лендинге может POST на `/api/leads` и получить `{"status":"success"}`
- [ ] Администратор логинится, видит заявки, создаёт новости
- [ ] Битрикс24 интеграция работает и тестируется из настроек
- [ ] Тесты покрывают: auth, lead validation, CSV export, Bitrix24 service
- [ ] Бинарник собирается командой `go build ./cmd/server` без CGO
